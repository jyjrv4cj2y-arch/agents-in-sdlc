GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。作業は開発者のコンピューター上でリアルタイムに進むため、VS Code の Copilot Chat では、ツールの呼び出しとファイル編集を逐一確認できます。各差分をインラインでレビューし、個別の変更を承認または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントにライトモードの切り替えを依頼し、ハイコントラストモードと併せて追加します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、各作業手順が表示されます。各ファイルの編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインに表示されます。
   - **Keep** を選択して変更を受け入れます。
   - **Undo** を選択して変更を取り消し、エージェントに再度作業してもらいます。
4. チャット上部の **Files changed** インジケーターを開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの呼び出し (たとえばターミナルコマンドの実行) で許可を求められると、エージェントは一時停止して **Allow** のプロンプトを表示します。許可するのは、実行してよいと判断したコマンドだけにしてください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。実施した変更をまとめた最終メッセージが表示されます。

## ライトモードの追加をエージェントに依頼する

ハイコントラストモードができたので、同じ会話を続けてライトモードの切り替え機能を追加します。同じチャットセッションを使うため、エージェントは前の作業のコンテキスト (変更したコンポーネント、採用したスタイル、設定したローカル ストレージのパターンなど) を保持します。

1. Copilot Chat の入力欄から、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調べて作業を再開し、ライトモードの追加を提案します。
3. 変更が追加されるたびにレビューし、ハイコントラストモードと同じように **Keep** または **Undo** を使います。
4. エージェントが望まない方法で作業を進めた場合 (たとえば、好みに合わない方法で切り替え UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を補う追加プロンプトを送ります。

> [!TIP]
> 進行中のセッションを方向付けると、最初からやり直すより速く進められます。追加プロンプトで変更を依頼できます (「CSS を簡潔にし、セレクターを重複させずに CSS 変数を使う」など)。作業方針を修正することも (「切り替えを 3 つに増やさず、既存の設定パネルにライトモードを追加する」など)、範囲を広げることもできます (「両方の切り替えにキーボードショートカットも追加する」など)。

## 作業ファイル全体をレビューする

変更をコミットする前に、エージェントが編集したファイル全体を簡単に確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ パターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカル ストレージによる設定の保持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って進行中のセッションを監視し、方向付けました。ファイル編集ごとにレビューし、変更を承認または取り消し、コンテキストを失わずに追加のプロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を承認または取り消す。
- セッションの途中で追加プロンプトを使って方向付ける。

次の[レッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
